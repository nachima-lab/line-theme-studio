# LINE着せかえ制作室

GitHub Pages向けの静的Webアプリです。素のHTML、CSS、JavaScriptで動作します。

## Phase 2　作品管理・全画像スロット・自動保存・バックアップ

- 「作品管理」で作品の新規作成、切り替え、名前変更、削除ができます。スキンと画像は作品ごとに保存され、前回開いた作品が再読み込み時に表示されます。
- カラースキンは9系統・50種類です。トーク画面で配色と背景を確認できます。ヘッダー文字は背景色に合わせて白または黒で表示します。
- 原画は全25枠です。メイン画像、トーク背景、メニュー背景、パスコードOFF／ON、プロフィール個人／グループ、メニューアイコン9機能のOFF／ONをそれぞれ登録、プレビュー、差し替え、取り外しできます。
- 原画は元のバイト列をIndexedDBに保存します。新規登録する長辺1024px超の画像は、ブラウザが生成できる場合に長辺1024pxの表示用コピーも保存します。移行・復元した画像のプレビューには原画を使用します。画像カードは必要になったときに読み込み、登録時のデコードは1枚ずつ処理します。

### 保存データの移行

初回起動時に既存の単一作品を「引き継いだ作品」として取り込みます。旧試作のメニューアイコン1枠は「メニューアイコン トーク OFF」に引き継ぎます。移行は同一IndexedDBトランザクション内で新しいキーに書き込みます。旧レコードは保持され、新形式の保存に失敗した場合も再試行できます。更新が競合したタブは保存エラーを表示し、そのタブの変更を全作品ZIPへ書き出せます。

### バックアップ

全作品の設定、最後に開いた作品、原画を日付入りのZIPで保存できます。全作品ZIPの読み込みは確認後に作品一覧を置き換えます。旧ZIPと旧JSONは確認後に1作品として追加します。復元データは検証し、IndexedDBへの書き込みが成功してから画面を切り替えます。

ブラウザのサイトデータを消す前に別の場所へZIPを保存してください。バックアップの画像は元の形式で格納します。ZIPは1ファイル80 MiB、内容の合計300 MiBまでです。端末のストレージ容量により、それ以下でも自動保存が失敗する場合があります。

## iPhone Safariでの確認手順

1. 既存データのある検証端末では事前にバックアップを保存し、同一オリジンで更新版を開きます。「引き継いだ作品」のスキン、トーク背景、メイン画像、メニューアイコン「トーク OFF」を確認します。
2. 「新規作成」で作品を2つ用意します。それぞれ別のスキン・画像を登録し、作品を切り替えて分離されていることを確認します。原画の登録、差し替え、取り外しを試します。
3. 「自動保存済み」を確認してSafariを再読み込みします。作品一覧、最後に開いた作品、プレビューが復元されることを確認します。
4. 「全作品ZIPを書き出す」で「ファイル」に保存します。検証用作品を削除し、ZIPを読み込みます。確認ダイアログを承認すると、作品一覧、最後に開いた作品、スキン、画像が復元されます。
5. 旧ZIPまたは旧JSONを読み込み、作品が追加されることを確認します。大きめの写真やHEICを登録して、トーク背景や原画プレビューが表示されるか確認します。

## Phase 3　提出用ZIP

1. 作品に原画25点を登録します。メニューアイコンは9機能それぞれのOFF／ON、パスコードはOFF／ONの2点を用意します。
2. 「切り出し位置と白判定を調整」を開き、メイン画像・メニュー背景・トーク背景の切り出しを確認します。スライダーは原画の上からの位置を示します。調整値は作品に自動保存し、全作品ZIPにも含めます。
3. 「62点を生成して検証する」を押します。未登録の原画は一覧に表示され、登録がそろうまで生成を開始しません。
4. 検証一覧でファイル名、寸法、容量を確認します。PNGの上限は各1,000,000バイトです。色数を減らした場合は該当行に表示し、検証に通らないファイルがある場合はダウンロードを出しません。
5. 「提出用ZIPをダウンロード」を押し、Safariのダウンロード一覧またはiPhoneの「ファイル」で、作品名と日付が付いたZIPを確認します。提出用ZIPにはPNG62点が直接入り、全作品ZIPには作品データと原画が入ります。

桃太郎ワールドのテストデータでは、参考画像2点を除く原画25点を登録します。出力したPNGのファイル名と縦横寸法を添付の `expected_files.csv` と照合します。背景の見え方は切り出しプレビューで確認できます。

## Phase 4　画面プレビュー

- 「トーク」「パスコード」「メニュー」のタブで切り替えます。タブの切り替え中も開いている作品とスキンは維持されます。
- パスコードは桁ごとにタップするか、テンキーでOFF／ONを確認できます。上部とテンキー部は選択したスキンの2色を使います。
- メニューは横にスワイプして9種を確認できます。アイコンを押すとそのアイコンがONになり、同じものをもう一度押すとOFFに戻ります。メニュー全体の色は仮表示です。
- パスコード、メニュー背景、メニューアイコンは、Phase 3のiOS用PNGと同じ加工を使います。プレビューの枠・ボタンは確認用で、PNGは縮小表示されます。Android用や小型メニュー用の別寸法は提出用ZIPで確認できます。


## Phase 6　制作サポート

- 作品にキャラ表1枚、固定色8色まで、画風・世界観のメモを保存できます。キャラ表は参照資料に使い、提出用62点には含めません。
- 8区分の指示文を作品ごとに編集できます。「コピー」は差し込み語を現在の固定色とメモに置き換えます。共通の初期文面は `js/production-data.js` で管理します。
- 色置換の下書きは元のOFF画像を保持し、採用した場合だけ対応するON枠を更新します。外周透過も市松模様の下書きで確かめてから採用できます。
- 外周透過の取り消しは各スロットの直前の1回分です。スロットの差し替えや削除で破棄されます。全作品ZIP v3には制作データと取り消し用画像も含みます。v2と旧形式の読み込みに対応しています。

### 部分ZIPのiPhone Safari実機検証

2026年11月26日、利用者による実機検証で全項目合格。対象機能は `468d3ad`、検証専用版は `3175829`。

- 0バイト画像を含む作品から部分ZIPを書き出せた。
- 未収録一覧に、メニュー背景、`zero-byte.png`、0バイトであることが表示された。
- 部分ZIPを読み込む前に、未収録画像があるという警告が表示された。
- 復元後、正常なメイン画像 `normal.png` と世界観メモが残り、メニュー背景は未登録になった。
- 検証は専用の保存領域で行い、既存の桃太郎ワールドへの影響はなかった。

### P1　原画と作品メタ情報の保存分離

IndexedDBの旧 `projects` ストアは残ります。初回は新ストアにコピーした画像を読み戻してサイズ・SHA-256を照合し、成功後に新形式を有効にします。途中で容量不足や画像異常が見つかった場合はエラーを表示し、旧データを保持します。中断後は再読み込みで再試行できます。

スキンや制作メモを編集しても画像ストアには書き込みません。原画・縮小画像・キャラ表・取り消し用画像は、それぞれ変更された画像だけを保存します。全作品ZIP v3の形式は従来どおりです。

DBのバージョンが2になるため、同じ保存元でバージョン1固定の旧版を開き直すとDBを開けません。旧レコードはP1のDB内に残ります。
